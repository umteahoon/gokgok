# 💾 Database Architecture & Data Flow

본 프로젝트는 서비스의 안정성과 확장성을 위해 **Supabase(PostgreSQL)** 클라우드 데이터베이스를 채택하였으며, 보안 중심의 데이터 설계에 집중했습니다.

---

## 🏗️ 1. 시스템 구조: "3층 건물" 비유
우리 프로젝트는 데이터가 유기적으로 움직이는 **3-Tier 아키텍처**로 설계되었습니다.

* **1층 (Frontend / React):** 사용자가 정보를 입력하고 확인하는 
**'접수 창구'**
* **2층 (Backend / Node.js & Express):** 데이터가 진짜인지 검사하고 암호화하는 **'관리실'**
* **3층 (Database / Supabase):** 정보를 영구적이고 안전하게 보관하는 **'거대한 창고'**

---

## 🛡️ 2. 데이터 보안 및 무결성 (Security & Integrity)
- **비밀번호 암호화:** `bcrypt` 라이브러리를 사용하여 단방향 해시 암호화를 적용했습니다. DB 관리자조차 사용자의 실제 비밀번호를 알 수 없도록 설계되었습니다.
- **중복 가입 방지:** `email` 컬럼에 `UNIQUE` 제약 조건을 설정하여 서버 및 DB 레벨에서 중복 가입을 원천 차단합니다.
- **권한 기반 제어 (RBAC):** `role` 컬럼을 통해 `USER`와 `ADMIN` 권한을 구분하며, 특정 이메일(``)에는 자동으로 관리자 권한을 부여하는 비즈니스 로직을 구현했습니다.

---

## 🔄 3. 데이터 이동 경로 (회원가입 예시)
실제 데이터가 사용자로부터 DB까지 도달하는 과정은 다음과 같습니다.

1.  **입력:** 사용자가 화면에서 이름, 이메일, 비밀번호를 입력하고 가입 버튼을 누릅니다.
2.  **전달:** Frontend가 이 정보를 들고 백엔드 서버(Render)로 **`fetch`** 요청을 보냅니다.
3.  **검문:** 서버는 비밀번호를 `bcrypt`로 암호화하고, 이미 가입된 이메일인지 검사합니다.
4.  **저장:** 모든 검문이 끝나면 최종 데이터만 **Supabase DB** 창고에 안전하게 저장됩니다.
5.  **응답:** 서버가 성공 메시지를 보내면, 화면에 "회원가입 완료" 알림이 뜹니다.

## 📊 4. Database Schema (Profiles Table)

| 컬럼명 | 데이터 타입 | 제약 조건 | 설명 |
| :--- | :--- | :--- | :--- |
| `id` | `uuid` | `PRIMARY KEY` | 유저 고유 식별자 (자동 생성) |
| `email` | `text` | `UNIQUE`, `NOT NULL` | 로그인 ID (이메일 주소) |
| `password` | `text` | `NOT NULL` | **암호화된 비밀번호** |
| `name` | `text` | `NOT NULL` | 사용자 이름 |
| `role` | `text` | `DEFAULT 'USER'` | 권한 (USER / ADMIN) |
| `created_at` | `timestamp` | `DEFAULT now()` | 가입 일시 |

## 🛠️ Infrastructure & Deployment

본 프로젝트는 안정적인 서비스 제공을 위해 검증된 클라우드 플랫폼을 활용하여 구축되었습니다.

### **1. Backend Server: Render**
- **역할:** Node.js/Express 애플리케이션 호스팅
- **설명:** GitHub 저장소와 연동하여 코드가 수정될 때마다 자동으로 빌드 및 배포(CI/CD)되는 환경을 구축했습니다. 프론트엔드의 요청을 받아 비즈니스 로직을 처리하고 DB와 통신하는 '중간 관리자' 역할을 수행합니다.

### **2. Database: Supabase**
- **역할:** 클라우드 관계형 데이터베이스(PostgreSQL)
- **설명:** 유저의 프로필 정보, 권한, 인증 데이터를 영구적으로 저장합니다. 강력한 보안 기능과 실시간 데이터 관리 대시보드를 제공하여 데이터의 무결성을 유지합니다.

---

## 🏗️ 시스템 아키텍처 (System Architecture)

전체적인 데이터 흐름은 다음과 같은 구조로 이루어져 있습니다.



1.  **Frontend (React / Netlify):** 사용자가 보는 화면이며, 입력을 받아 API 요청을 보냅니다.
2.  **Backend (Express / Render):** 요청을 받아 암호화(bcrypt), 인증(JWT) 등 핵심 로직을 처리합니다.
3.  **Database (PostgreSQL / Supabase):** 최종 승인된 데이터를 저장하고 관리합니다.

---

## 🔄 데이터 흐름 예시 (Render & Supabase 협업)

1.  **사용자:** 가입 버튼 클릭 (리액트)
2.  **Render 서버:** 전달받은 비밀번호를 암호화하여 보안 처리
3.  **Supabase DB:** 서버가 보낸 데이터를 테이블의 각 컬럼에 맞게 영구 저장
4.  **확인:** DB 저장 완료 후 서버를 거쳐 사용자 화면에 결과 표시
